Telemetry Pipeline
Management Tools

A cloud-based telemetry processing platform that collects, filters, routes, and monitors high-volume application logs and system events.

// tech stack

  • Frontend Typrscript, Vue
  • Backend Go, AWS Lambda, Amazon API Gateway
  • Database PostgreSQL, Amazon RDS, Redis
  • Other OpenTelemetry, AWS SQS, AWS CloudWatch, Docker, GitHub Actions, Jest, Cypress, GitHub

The Problem

Modern software systems generate large volumes of logs, metrics, traces, and event data, but engineering and operations teams often struggle to manage that telemetry efficiently across cloud, hybrid, and distributed environments. Without a structured pipeline, telemetry data can become expensive, noisy, difficult to search, and hard to route to the right monitoring or analytics tools. I wanted to build a platform that gives teams better control over how telemetry is collected, filtered, transformed, and delivered.

The Solution

I built a telemetry pipeline management platform that collects application logs and system events, applies configurable filtering and routing rules, and forwards structured data to downstream monitoring systems. The platform uses TypeScript, Node.js, RESTful APIs, AWS services, and a scalable backend architecture to support reliable ingestion and processing. It includes dashboard views for pipeline status, error tracking, delivery results, and operational visibility, helping teams manage telemetry with better control, observability, and resilience.

Challenges

Designing the system required careful planning around high-volume data ingestion, secure API access, scalable backend services, and reliable event processing. I had to structure pipeline rules, routing logic, retry handling, and failure tracking so the platform could process telemetry consistently without losing important operational data. Building observability into the platform itself, tuning backend performance, securing API workflows, and keeping the user interface clear for complex pipeline activity added meaningful technical complexity.

AccessCore IAM System

A Java-based identity and access management platform that centralizes authentication, authorization, SSO, federation, policy enforcement, and zero trust access workflows for secure enterprise applications.

View Project ↗

// tech stack

  • Frontend JavaScript, HTML, CSS, responsive web pages
  • Backend Java, Spring Security, Java EE, REST services, identity services
  • APIs OAuth 2.0, OpenID Connect, SAML, WebAuthn, REST APIs, LDAP APIs
  • Other OpenAM, OpenSSO, SSO, Zero Trust Architecture, AAA, access control, accounting, authentication

The Problem

Enterprise applications often need secure access across many users, systems, and environments, but managing authentication, authorization, federation, and single sign-on separately can create inconsistent security controls. Without a centralized IAM system, teams may struggle with user identity, policy enforcement, token validation, Active Directory integration, audit tracking, and secure access for internal and external applications. I wanted to build an access management platform that brings authentication, authorization, SSO, federation, and policy-based security into one structured system.

The Solution

AccessCore IAM System is an identity and access management platform inspired by OpenAM and OpenSSO concepts, focused on secure authentication, authorization, federation, and centralized access control. The system supports SSO, OAuth 2.0, OIDC, SAML, Kerberos, WebAuthn, Active Directory integration, policy management, token validation, session handling, and audit logging. I used Java as the primary backend language with JavaScript, HTML, and CSS for administrative and authentication interfaces, creating a secure IAM foundation for enterprise applications and zero trust access workflows.

Challenges

The main challenge was designing a reliable identity platform that could support multiple authentication and federation standards while keeping access policies consistent across different applications. I had to organize complex IAM concepts such as AAA, OAuth 2.0, OIDC, SAML, Kerberos, WebAuthn, SSO, Active Directory, policy evaluation, session management, and authorization decisions into a clear and maintainable system. Balancing security, usability, federation workflows, token handling, audit logging, and zero trust architecture added meaningful complexity because every access decision needed to be secure, traceable, and predictable.

CareFlow HealthOps Platform

a Python-based healthcare workflow automation backend system designed to manage patient records, care coordination, consultation history, facility operations, provider workflows, and clinical task tracking through a secure and scalable digital health platform.

// tech stack

  • Frontend HTML, Dajngo, Templates, Responsive UI, facility management dashboards
  • Backend Pyton, Django, Django Rest Framework, healthcare workflow services, facility operation services
  • APIs REST APIs, authentication, consultation history, facility management apis
  • Other Docker, Nix, Shell scripting, Makefile, GitHub, digital public goods

The Problem

Healthcare teams often manage patient intake, consultation history, care coordination, facility operations, and provider workflows across disconnected systems, spreadsheets, or manual processes. This can make it difficult to track patient status, coordinate clinical tasks, manage facility-level operations, and maintain clear healthcare records. I wanted to build a structured healthcare workflow automation platform that supports digital health operations with better visibility, consistency, and operational control.

The Solution

CareFlow HealthOps Platform provides a centralized healthcare workflow system for managing patients, providers, facilities, consultation history, care coordination, and clinical task tracking. The platform uses Python as the primary backend language with Django and Django REST Framework to build secure healthcare services and REST APIs. PostgreSQL supports structured healthcare data, while Docker, Nix, Shell scripting, and Makefile workflows support development, deployment, and environment consistency for an open-source digital public goods style healthcare platform.

Challenges

The main challenge was designing clean healthcare data models and secure APIs while keeping clinical workflows simple, scalable, and easy to manage.

Openship

A deployment automation system designed for CMS and eCommerce teams to manage website releases, serverless APIs, build pipelines, environment configuration, form workflows, integrations, and production monitoring through a reliable Git-based delivery process.

View Project ↗

// tech stack

  • Frontend React, Typescript, Next.js, Tailwind CSS
  • Backend Node.js, TypeScript, Deployment orchestration services, agent communication services
  • APIs REST APIs, deployment APIs, build status APIs, release history APIs, webhook APIs
  • Other Self-hosted architecture, deployment agents, Docker, Github Integration, CI/CD, Shell Scripts, production logs

The Problem

CMS and eCommerce engineering teams often rely on fragmented deployment scripts, manual release steps, and inconsistent environment configurations, which increases delivery risk and makes production releases harder to control. Without a centralized deployment platform, teams can struggle to track build status, monitor deployment health, manage rollback workflows, and maintain visibility across self-hosted applications.

The Solution

Built a TypeScript-based self-hosted deployment platform that centralizes application builds, release automation, deployment agents, environment configuration, and Git-based delivery workflows. The platform provides deployment tracking, build execution, webhook-driven automation, production log visibility, and rollback support, helping engineering teams deliver CMS and eCommerce applications with greater consistency, reliability, and operational control.

Challenges

The main challenge was designing an agent-based deployment architecture that could securely coordinate builds, deployment execution, environment variables, status updates, logs, and rollback workflows across self-hosted infrastructure. I also had to balance automation, reliability, and maintainability while ensuring the platform could support repeatable releases, clear operational visibility, and scalable deployment workflows.

ChatReview is an AI-assisted natural language processing framework designed to analyze domain-specific user reviews and convert unstructured feedback into meaningful insights. The framework uses ChatGPT to identify sentiment, recurring topics, user concerns, feature requests, and experience patterns that are often difficult to capture through traditional keyword-based review analysis.

It supports review preprocessing, prompt-based classification, theme extraction, sentiment interpretation, and summary generation, making it easier to evaluate customer needs, product weaknesses, and improvement opportunities.

It highlights how ChatGPT-enabled workflows can improve review analysis by adding context-aware interpretation, domain-specific reasoning, and scalable insight generation. It demonstrates practical experience with NLP, prompt engineering, text classification, review mining, qualitative analysis, and AI-powered data interpretation.
